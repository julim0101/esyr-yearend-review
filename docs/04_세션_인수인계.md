## 2. 무엇을 만들었나

### 핵심 문제 정의

> **파일은 계속 쌓이는데, "어디까지 봤는지"는 사람 기억에만 있다.**

PDF 안에는 "이 파일이 저 파일의 수정본"이라는 정보가 **없다.**
파일명도 못 믿는다 — 같은 이름인데 내용이 다르고, 다른 이름인데 내용이 같다.

### 개념 4개 분리 (이게 전부다)

| 개념 | 뜻 |
|---|---|
| `DocumentGroup` | 하나의 논리적 서류 ("A기관 기부금영수증") |
| `DocumentVersion` | 그 서류의 제출본 (최초 / 수정1차 / 수정2차) |
| `ExtractionRun` | 한 버전을 *읽은* 결과 판본 (재추출하면 revision_no 증가) |
| `Review` | 특정 버전 + 특정 판본에 대한 확인 기록 |

**문서 버전과 추출 판본을 절대 혼동하지 말 것.**

### 절대 어기면 안 되는 판정 원칙

1. 읽지 못한 값을 0이나 빈 문자열로 바꾸지 않는다 → '변경 없음'이 되어버린다
2. 기존 항목이 안 보여도 '삭제'로 확정하지 않는다 → 추출 실패일 수 있다
3. 금액이 같다는 이유로 같은 항목으로 연결하지 않는다 → 식별정보로 연결
4. **합계가 같아도 세부내역이 바뀌면 잡아낸다**
5. 파일이 달라지면 값이 같아도 자동 완료하지 않는다
6. 임의의 정확도 백분율을 만들지 않는다

### 비교 기준 = "가장 최근 검토 완료 버전"

```
V1 검토완료 → V2 미검토 → V3 제출
   ↑ 기준        ↑ 여기가 기준이면 V1→V2 변경분이 영원히 묻힌다
```

## 4. 실제로 밟은 함정 — 같은 실수 반복 금지

### 4-1. SQLAlchemy 관계 캐시 (버그 → 수정)

같은 세션에서 `run_extraction()` 직후 `version.runs`를 읽으면 **빈 목록**이 나온다.
→ 관계 대신 직접 조회 프로퍼티로 변경.

### 4-2. 그게 목록 화면을 27초로 만들었다 (성능 → 수정)

프로퍼티가 매번 DB를 치는데 대시보드가 묶음마다 3번씩 호출 → 왕복 50회 이상.
→ `build_group_states()` 로 4회 조회 후 파이썬에서 조립.

### 4-3. 함수 리전과 DB 리전 불일치 (가장 큰 성능 요인)

Vercel 기본은 미국, Supabase는 서울.
→ `vercel.json` 에 `"regions": ["icn1"]`

**27.5초 → 0.23초 (약 90배)**

### 4-4. 비밀번호 해시 3초

Werkzeug 기본 `scrypt` 가 서버리스 CPU에서 느림.
→ `pbkdf2:sha256:120000`. **3.0초 → 0.55초**

### 4-5. Vercel 번들 292MB > 225MB 제한

`psycopg[binary]` 가 수십 MB.
→ **pg8000** 교체 + `.vercelignore`

### 4-6. 서버리스 읽기 전용 파일시스템

`os.makedirs` 가 앱을 죽임 → 예외 처리 + 안내 메시지.

### 4-7. PowerShell 파이프가 환경변수를 깨뜨림

`$v | vercel env add KEY` → BOM·개행 혼입 → `Could not parse SQLAlchemy URL`
→ bash `printf '%s'` 로 등록. 앱에도 `lstrip("\ufeff")` 방어.

### 4-8. OCR 관련 (여러 개)

- `pytesseract` 는 래퍼일 뿐. 엔진(Tesseract)과 언어데이터(`kor`)는 별도 설치
- 언어데이터 경로에 **한글·공백** 있으면 실패 → `%LOCALAPPDATA%\esyr\tessdata`
- `--tessdata-dir "경로"` 처럼 **따옴표 붙이면 경로의 일부가 됨** (pytesseract가 split함)
- `get_languages()` 는 한국어 Windows에서 cp949 인코딩 에러 → 파일 존재로 판정

### 4-9. ONNX OCR 검증 — 채택하지 않음

Vercel에 Tesseract를 못 깔아서 `rapidocr-onnxruntime` 을 실측했다.

| | 한글 | 금액 |
|---|---|---|
| Tesseract (로컬) | `사단법인 행복나눔재단` ✅ | ✅ |
| ONNX 기본(중국어) | `草居民局` ❌ | `150,000` ✅ |
| ONNX 한국어 모델 | `김하들` △ | **`15001`** ❌ |

**한국어 모델이 금액을 오독한다.** 금액 검증 도구에서 금액이 틀리면 없느니만 못하다.
→ 배포본에서 OCR을 끄고 `추출 확인 필요` 로 남기는 것이 **설계상 선택**이다.
