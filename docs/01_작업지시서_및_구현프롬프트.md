# Part 1. 작업지시서

## 프로젝트 개요

연말정산 담당자가 직원의 간소화자료 및 개별 증빙 PDF를 검토한 뒤 추가자료나 수정본을 받으면,
무엇을 다시 확인해야 하는지 찾고 기존 검토 기록과 연결해야 한다.
이 과정을 지원하는 웹 프로그램을 개발한다.

## 개발 요청사항

1. **Python Flask 기반으로 제작** — 검토 기록과 제출 버전은 데이터베이스에 보관한다.
2. **직원별 PDF 자료함** — 직원·귀속연도·서류 종류를 지정해 업로드한다.
   새 서류 추가와 기존 서류 수정본 제출을 구분하고, 기존 원본과 제출 이력을 보존한다.
3. **PDF 내용 추출 및 OCR** — 텍스트 페이지는 직접 추출, 스캔 페이지는 OCR.
   원본과 추출값을 함께 보여주고 담당자가 수정·확인할 수 있게 한다.
4. **수정본 비교** — 같은 직원·귀속연도·서류의 이전 검토본과 수정본을 비교한다.
   항목 추가·변경·삭제 후보 및 읽기 실패를 구분하고, 변경된 값과 근거 페이지를 표시한다.
5. **검토 상태 및 이력 관리** — 신규 검토, 재확인 필요, 추출 확인 필요, 검토 완료.
   변경되지 않은 기존 자료의 검토 기록을 유지하고, 누가 언제 어느 버전을 확인했는지 기록한다.
6. **담당자 대시보드** — 제출 현황·미검토·재확인·처리 실패 조회, 검색·필터, CSV 다운로드.
7. **시연 자료 및 실행 안내** — 가상 PDF의 최초·추가·수정 제출 사례와 실제 검증 결과.

## 대표 시연 장면

> 직원 A의 간소화자료와 기부금영수증을 검토 완료한다.
> 이후 기부금영수증 수정본을 등록하면 금액 100,000원 → 150,000원 변경 후보가 표시된다.
> 기존 간소화자료의 검토 완료는 유지하고, 수정된 영수증만 재확인한다.
> 담당자가 원본을 확인하고 완료하면 확인자·시각·버전이 기록된다.

## 1차 버전에서 완료할 범위

- 담당자 로그인 및 자료 등록
- 간소화자료의 지원 서식 추출·비교
- 지정한 기부금영수증 서식 1종의 텍스트 PDF 및 스캔 PDF 추출·비교
- 지원 범위 밖 서류의 업로드·원본 조회·수동 검토 기록
- 수정 이력, 재검토 처리, 대시보드, CSV

직원 직접 제출 포털, 회사 계정 연동, HRIS 연동, 자동 메일 발송은 후속 범위로 둔다.
**공제 가능 여부·세액 계산·위변조 판정은 이번 프로그램에서 수행하지 않는다.**

# Part 2. 상세 구현 프롬프트

**아래 '프롬프트 시작'부터 '프롬프트 끝'까지 개발자 또는 코딩 AI에게 전달하면 됩니다.**

## 프롬프트 시작

너는 문서 처리와 업무용 웹 애플리케이션 개발 경험이 있는 Python 개발자야.
아래 요구사항에 맞춰 **ESYR(Etners Smart Year-end Review) — 연말정산 증빙 PDF 추가·수정
제출자료 검토 관리** 프로그램을 구현해줘.
계획이나 정적인 화면만 제공하지 말고, 실제 PDF를 업로드하여 추출·비교·검토를 수행할 수 있는
실행 가능한 앱과 소스를 제공해줘.

### 1. 문제와 완료 목표

담당자는 직원이 제출한 간소화자료와 개별 증빙 PDF를 확인한다.
검토 후 추가자료나 수정본이 들어오면 이전에 확인한 내용, 새로 들어온 내용,
다시 확인할 내용을 구분해야 한다.

1. 신규 서류와 수정본을 정확히 연결한다.
2. 기존 검토 기록을 보존하면서 수정된 자료를 재검토 대상으로 표시한다.
3. 비교 결과에서 해당 원본 페이지를 바로 확인할 수 있다.
4. 추출 실패나 지원하지 않는 내용을 완료·변경 없음으로 오인하지 않는다.
5. 실제로 실행한 검증과 남은 제한사항을 보고한다.

이 앱의 '검토 완료'는 담당자가 해당 자료 버전을 확인했다는 의미야.
세법상 공제 적격이나 연말정산 신고 완료를 의미하지 않아. 화면과 보고서에서도 명확하게 해줘.

### 2. 사용자와 개발 범위

**필수 기능 P0**
- 담당자 계정으로 로그인한다. 공개 회원가입은 제공하지 않는다.
- 담당자는 자신에게 배정된 직원 자료만 열람·등록·검토한다.
- 관리자는 직원과 담당자 배정을 관리하고 전체 진행 현황을 확인한다.
- 과제용 초기 데이터로 관리자 1명, 담당자 2명, 가상 직원 5명을 제공한다.

**개선 기능 P1** — 직원 직접 제출 포털, 지원 서식 확대, 중복 후보 표시, PDF 내 강조 표시

**후속 검토 P2** — 사내 인증·HRIS 연동, 다중 운영 환경, 알림 연동

P0를 먼저 완성해줘. 구현되지 않은 P1·P2는 화면에서 사용할 수 있는 기능처럼 표시하지 마.

### 3. 구현 구성

- 백엔드: Python Flask, 기능별 Blueprint 분리
- 프런트엔드: Jinja2, HTML/CSS, JavaScript
- DB: SQLAlchemy + SQLite. PostgreSQL 전환이 어렵지 않게 구성
- 로그인: 세션 기반 인증, 비밀번호 해시 저장, CSRF 보호
- PDF 텍스트·페이지 정보 / 렌더링: 좌표 추출과 로컬 렌더가 가능한 도구
- OCR: Tesseract + 한국어·영어 언어데이터
- OCR 실행파일과 언어데이터는 Python 패키지만 설치하면 준비되는 것으로 가정하지 말고,
  별도 설치·확인 방법을 제공해줘.

Windows PC에서 실행할 수 있도록 해줘. 설치 후 문서 분석은 로컬에서 수행하고
**외부 OCR·AI API를 호출하지 마.** 기본 접속 주소는 127.0.0.1로 제한해줘.

### 4. 화면 구성

**A. 대시보드** — 귀속연도 선택, 상태별 집계, 검색·필터, 미완료 목록, 상태 갱신

**B. 직원별 자료함** — 서류별 현재 버전과 검토 상태, 제출 이력(신규/추가/수정),
'새 서류 추가'와 '기존 서류 수정본 등록' 버튼

**C. 업로드** — 직원·귀속연도·서류 종류·표시명·제출 구분을 확인한 뒤 업로드.
수정본이면 교체할 기존 서류를 지정한다.
> 한 직원에게 같은 종류의 영수증이 여러 장 있을 수 있으므로 '직원+서류 종류'만으로 자동 교체하지 마.
> 파일명이나 OCR로 추출한 성명만으로 직원이나 수정 대상을 확정하지 마.

**D. 추출 결과 확인** — 왼쪽 원본 PDF, 오른쪽 추출 항목·값·페이지·방식·확인 상태.
추출값 수정과 사유 기록. 읽지 못한 페이지와 미지원 서식 안내.

**E. 수정본 비교·검토** — 이전 검토본과 현재 수정본을 나란히.
항목별 이전값·새 값·변경 종류·원본 페이지. '현재 버전 검토 완료' 버튼.
> 원본 위치를 정확히 계산하지 못한 경우 해당 페이지로 이동하게 해줘. 잘못된 위치에 강조 표시하지 마.

### 5. PDF 입력과 추출 규칙

- 1차 입력은 PDF로 제한. 기본 제한 파일당 20MB, 50페이지 (설정 변경 가능)
- 확장자뿐 아니라 실제 PDF 파싱 가능 여부를 확인한다
- 암호화된 PDF는 '암호 해제 후 다시 제출해 주세요'로 안내한다
- 원본은 서버의 비공개 저장 경로에 변경 없이 보관한다

**페이지별 추출**
1. 각 페이지에서 텍스트 추출을 시도한다
2. 텍스트가 없거나 깨졌으면 해당 페이지를 OCR로 읽는다
3. OCR 원문, 정규화한 값, 사람이 수정한 값을 구분해 저장한다
4. 모든 추출값에 파일 버전 ID, 페이지 번호, 추출 방식을 기록한다

> 텍스트가 몇 글자 나온다는 이유만으로 페이지 전체를 정상 추출했다고 판단하지 마.
> OCR 점수는 참고 정보로만 사용하고 임의의 정확도 백분율을 만들어 표시하지 마.

**1차 자동 추출 항목**

| 서류 | 근거 서식 | 추출 항목 |
|---|---|---|
| 기부금영수증 | 소득세법 시행규칙 [별지 제45호의2서식] | 일련번호, 기부자 성명·주소, 단체명·사업자등록번호, 근거법령, 기부내역(코드·구분·연월일·품명·금액), 합계 |
| 간소화자료 | 「OOOO년 귀속 소득ㆍ세액공제증명서류 : 기본내역 [항목]」 | 귀속연도, 항목, 가입자 성명·주민등록번호, 월별 금액, 합계 |
| 기타·미지원 | — | 파일·페이지 정보와 추출 원문, 수동 검토 기록 |

> 간소화자료는 본인과 가족 등 여러 대상자가 포함될 수 있으므로 추출한 모든 항목을
> 업로드 직원 본인의 지출로 취급하지 마. 항목 소유자를 구분할 수 없으면 수동 확인 대상으로 남겨줘.
>
> 가상 샘플로만 검증했다면 '가상 서식 지원'이라고 명시하고 홈택스 원본 전체 지원을 주장하지 마.

### 6. 서류·버전·중복 처리

다음 개념을 분리해줘.

- **서류 묶음(DocumentGroup)** — 같은 직원·귀속연도의 논리적 서류 하나
- **파일 버전(DocumentVersion)** — 최초 제출본, 2차 수정본, 3차 수정본
- **검토 기록(Review)** — 특정 파일 버전 및 추출 판본에 대한 확인 기록

**규칙**
1. 새 영수증 추가는 새 서류 묶음을 만든다. 기존 영수증을 교체하지 않는다.
2. 수정본은 사용자가 지정한 묶음에 새 버전으로 추가한다.
3. 직원이나 귀속연도가 다른 서류를 수정 대상으로 연결하는 요청은 서버에서 차단한다.
4. 현재 파일과 바이트가 같은 재업로드는 SHA-256으로 확인하고 중복 접수로 처리한다.
5. 과거 버전과만 같은 파일이 들어오면 '과거 제출본 재등록'으로 표시하고 확인을 요구한다.
6. 파일명이 같아도 내용이 다르면 수정 후보가 된다.
7. 다른 직원 자료의 존재 여부가 해시 중복 메시지로 노출되지 않게 한다.

### 7. 수정본 비교와 완료 기록 유지

**비교 기준**
- 기본 비교 기준은 해당 묶음의 **가장 최근 검토 완료 버전**이다.
- 검토 완료 버전이 없으면 직전 제출본과 비교하되 '최초 검토 미완료' 표시를 유지한다.
- V1 검토완료 → V2 미검토 → V3 제출이면 재검토 기준은 V1과 V3이다. V2 기록도 보존한다.

**항목 연결**
- 간소화 항목은 대상자·귀속연도·항목 종류로, 기부금 내역은 기관·영수증 번호·기부일로 연결한다.
- **같은 금액이라는 이유만으로 같은 내역으로 연결하지 않는다.**
- 연결 가능한 후보가 여러 개거나 식별정보가 부족하면 '대응 항목 확인 필요'로 남긴다.

**변경 표시** — `신규 항목` / `값 변경` / `기존 항목 미발견` / `비교값 동일` / `추출·대응 확인 필요`
- 쉼표·통화 단위·공백 같은 표현 차이는 정규화한다.
- **합계가 같아도 세부내역이 바뀔 수 있으므로 합계만 비교하여 동일 처리하지 않는다.**
- 기존 항목이 새 추출 결과에 없다고 바로 삭제로 확정하지 않는다.
- **읽지 못한 값을 0이나 빈 문자열로 바꾸어 '변경 없음'으로 처리하지 않는다.**

**검토 완료 유지 조건**
- 새 버전이 들어오지 않은 다른 묶음의 완료 상태는 유지한다.
- 파일이 달라졌다면 일부 추출값이 같아도 새 버전을 자동 완료하지 않는다.
- 추출 실패·미지원 영역은 자동 비교로 해결된 것으로 처리하지 않는다.
  담당자가 원본을 직접 검토했다는 기록과 사유를 남긴 경우 수동 완료할 수 있다.
- **페이지를 렌더링할 수 없어 원본을 보지 못한 파일은 앱에서 검토 완료할 수 없게 한다.**

### 8. 상태 및 집계 기준

| 구분 | 상태 |
|---|---|
| 추출 작업 상태 (기계) | 대기 / 처리 중 / 성공 / 부분 성공 / 실패 |
| 검토 상태 (사람) | 신규 검토 / 재확인 필요 / 추출 확인 필요 / 검토 완료 |

```
현재 제출 서류 수 = 선택한 귀속연도·권한·필터에 속한 서류 묶음 수
검토 완료율 = 현재 유효 버전의 검토가 완료된 묶음 수 / 현재 제출 서류 수 × 100
```

> '제출된 자료 검토 완료율'이라고 표시한다.
> 모든 필수 서류 제출 여부나 신고 준비 완료율로 표현하지 않는다.

### 9. 데이터 모델

`User` / `Employee` / `DocumentGroup` / `DocumentVersion` / `ExtractionRun` /
`ExtractedField` / `FieldCorrection` / `Comparison` / `Review` / `AuditEvent`

> 문서 버전과 추출 실행 결과를 혼동하지 마.
> 같은 원본을 OCR로 다시 읽었다고 제출 버전이 추가되는 것은 아니야.
> 재추출 결과는 새 추출 판본으로 저장하고, 이미 완료된 검토가 참조한 판본은 유지해줘.

### 10. 문서 보관과 접근

- PDF 원본·페이지 이미지·추출값·내보내기 모두 서버에서 권한을 확인한다.
- 파일은 public/static 폴더에 두지 말고 인증된 경로로 제공한다.
- 저장 이름은 서버에서 생성하고 업로드 파일명을 경로로 직접 사용하지 않는다.
- 비밀번호, PDF 본문, 주민등록번호 등은 일반 로그에 기록하지 않는다.
- 원본에 포함된 개인정보가 자동으로 익명화된다고 안내하지 않는다.
- 로컬 DB와 파일을 저장한다는 사실을 사용자에게 안내한다.

### 11. 내보내기

현재 필터 결과를 CSV로 다운로드한다. UTF-8 BOM, 수식 실행 위험 처리, 사번 앞자리 0 보존.
기본 현황 CSV에는 증빙의 전체 금액·민감한 본문을 넣지 않는다.

### 12. 가상 샘플과 검수

**모든 문서에 '시연용 가상자료'라고 표시하고, 실제 국세청 발급 문서처럼 주장하지 마.**

필수 사례 — 최초본/수정본, 스캔 PDF, 신규 추가본, 동일 파일 재제출,
**합계는 같지만 내역이 달라진 사례**, 읽기 어려운 스캔, 미지원 서식, 암호화 PDF, 손상 PDF

체크리스트는 `docs/03_검증체크리스트.md` 참조. 실제로 검증하고 결과를 그대로 보고해줘.

> **가상 스캔 PDF를 실제 OCR 엔진으로 처리한다.**
> 파일명에 따라 정해둔 값을 반환하는 가짜 분석으로 대체하지 마.
>
> 검증하지 않은 실제 간소화 서식의 정확도나 업무 절감률을 만들어내지 마.

### 13. 개발 순서와 산출물

1. **제출·버전·검토 흐름** — 로그인, 자료함, 업로드, 신규/수정 구분, 원본 보기, 버전 보존
2. **읽기와 비교** — 텍스트 추출, 스캔 OCR, 지원 서식 파싱, 버전 비교, 변경 후보 표시
3. **업무 화면과 검증** — 대시보드, 검색·필터, CSV, 가상 시연, 권한·충돌·추출 실패 검증

**산출물** — 전체 소스, 버전 고정 의존성, DB 초기화 절차, OCR 설치·진단 방법,
Windows 실행 안내, 가상 PDF 세트, 자동 테스트 결과, 지원 서식·제한사항 표, 3분 시연 순서

먼저 P0 구현 구조와 주요 가정을 짧게 설명하고 구현을 시작해줘.
지원하지 않는 서식을 만났다면 수동 검토 경로를 제공하고 제한사항을 명시해줘.
**OCR이 실행되지 않거나 실제 서식이 검증되지 않았다면 완료 보고에서 분명히 구분해줘.**

# Part 3. 한 문장 요약

> 직원이 제출한 연말정산 PDF의 추가·수정 이력을 관리하고, 마지막으로 검토한 버전과 비교하여
> 다시 확인할 부분을 보여주는 Flask 프로그램. 읽을 수 있는 PDF는 직접 추출하고
> 스캔 자료는 OCR로 읽으며, 원본과 추출값을 담당자가 확인할 수 있어야 한다.

## 시연 시나리오

1. 직원 A의 최초 간소화자료와 기부금영수증 등록
2. 원본·추출값을 확인하고 검토 완료
3. 새로운 영수증 추가 → 기존 완료 자료 유지, 새 서류만 신규 검토
4. 기존 영수증 수정본 등록 → 변경 후보와 이전 검토 기록 표시
5. 담당자 재확인 → 현재 버전 완료 및 이력 저장
6. 읽기 실패 사례 → 추출 확인 필요로 남기고 수동 검토

## 착수 전 확인할 사항

| 확인 주체 | 항목 | 과제용 기본값 |

| 업무 담당자 | 기존 내부 시스템의 수정본 비교·검토 승계 기능 | 중복 여부 미확인. 새 기능이라고 단정하지 않음 |
