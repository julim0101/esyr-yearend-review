# ESYR 기능설명서

> **ESYR** · Etners Smart Year-end Review
> 연말정산 증빙 PDF 추가·수정 제출자료 검토 관리
>
> https://esyr-yearend-review.vercel.app
> 시연 계정 — `manager1` / `esyr1234` (담당자) · `admin` / `esyr1234` (관리자)

---

## 이 도구가 하는 일

직원이 낸 연말정산 증빙을 담당자가 확인한 뒤, **추가본·수정본이 다시 들어왔을 때**
무엇이 달라졌고 무엇을 다시 확인해야 하는지 골라내는 도구입니다.

이미 확인이 끝난 자료의 검토 기록은 그대로 유지합니다.

> **'검토 완료'는 담당자가 해당 자료 버전을 확인했다는 뜻입니다.**
> 세법상 공제 적격이나 연말정산 신고 완료를 의미하지 않습니다.

---

## 화면 1 · 로그인

담당자 계정으로 접속합니다. **공개 회원가입은 없습니다.**

- 관리자 1명, 담당자 2명, 가상 직원 5명이 초기 데이터로 들어 있습니다
- 담당자는 자신에게 배정된 직원 자료만 볼 수 있습니다

---

## 화면 2 · 검토 현황 (대시보드)

귀속연도를 고르면 그 해의 검토 상태가 한눈에 보입니다.

### 지표 6개

| 지표 | 뜻 |
|---|---|
| 제출된 서류 | 이 귀속연도에 등록된 서류 묶음 수 |
| 검토 완료 | 현재 버전까지 확인이 끝난 것 |
| 재확인 필요 | 수정본이 들어와 다시 봐야 하는 것 |
| 추출 확인 필요 | 읽지 못했거나 지원하지 않는 서식 |
| 신규 검토 | 처음 들어온 서류 |
| 검토 완료율 | 완료 ÷ 제출된 서류 |

> 완료율은 **제출된 자료 기준**입니다. 모든 필수 서류가 제출됐는지,
> 신고 준비가 끝났는지를 뜻하지 않습니다.

### 검색·필터

사번 · 성명 · 서류명으로 검색하고, 검토 상태와 서류 종류로 거를 수 있습니다.

### 추출 작업 상태 (별도 영역)

기계가 읽은 결과입니다. 위의 검토 상태(사람이 확인한 것)와 **구분해서** 봅니다.
대기 / 처리 중 / 성공 / 부분 성공 / 실패

### CSV 내보내기

현재 필터 결과를 내려받습니다.
사번·성명·귀속연도·서류명·현재버전·검토상태·변경요약·검토자·검토시각.

- UTF-8 BOM으로 엑셀에서 한글이 깨지지 않습니다
- 사번 앞자리 0이 보존됩니다
- 증빙의 전체 금액·민감한 본문은 넣지 않습니다

## 화면 3 · 직원별 자료함

한 직원의 서류를 모아서 봅니다.

서류마다 **제출 이력 전체**가 보입니다.

```
행복나눔재단 기부금영수증
  최초 제출   01/05 14:20   신규   [검토 완료]
  수정 1차    01/12 09:15   수정
```

- 현재 버전이 아닌 것은 흐리게 표시됩니다
- 각 버전을 눌러 그때의 원본과 검토 기록을 볼 수 있습니다
- `수정본` 버튼으로 그 서류에 새 버전을 올립니다

## 화면 4 · 자료 등록

담당자가 직원에게 받은 PDF를 대신 등록합니다.

### 입력 항목

1. **직원** — 배정된 직원만 목록에 나옵니다
2. **귀속연도**
3. **제출 구분** — `새 서류 추가` 또는 `기존 서류의 수정본`
4. 새 서류면 — 서류 종류(간소화자료/기부금영수증/기타)와 표시명
5. 수정본이면 — **교체할 기존 서류를 직접 지정**
6. PDF 파일

### 안전장치

| | |
|---|---|
| **자동 교체 안 함** | 같은 종류 영수증이 여러 장일 수 있어, '직원+서류 종류'만으로 교체하지 않습니다 |
| **파일명으로 판단 안 함** | 파일명이나 OCR로 읽은 성명으로 직원·수정 대상을 확정하지 않습니다 |
| **실제 PDF인지 확인** | 확장자만 믿지 않고 실제로 열리는지 검사합니다 |
| **암호화 PDF** | "암호 해제 후 다시 제출해 주세요"로 안내합니다 |
| **용량 제한** | 파일당 20MB · 50페이지 (설정 변경 가능) |

### 중복 제출 처리

파일 **내용의 해시(SHA-256)** 로 판단합니다. 파일명·크기로 판정하지 않습니다.

| 상황 | 처리 |
|---|---|
| 현재 파일과 내용이 완전히 같음 | 중복 접수. 새 버전을 만들지 않고 검토 상태를 유지 |
| 과거 버전과만 같음 | "과거 제출본 재등록"으로 표시. 현재 상태를 되돌리지 않음 |
| 파일명만 같고 내용이 다름 | 정상적인 수정 후보로 처리 |

> 다른 직원 자료의 존재 여부가 중복 메시지로 새어나가지 않습니다.

## 화면 5 · 추출 결과 · 수정본 비교 (핵심 화면)

### 왼쪽 — 원본 PDF

**세 가지로 전환할 수 있습니다.**

| 탭 | 보이는 것 |
|---|---|
| **현재** | 방금 올린 수정본 |
| **기준** | 비교 기준이 된 예전 버전 |
| **나란히** | 두 본을 좌우로 동시에 |

페이지를 넘기면 양쪽이 같이 넘어갑니다.

> 페이지 순서가 바뀌었을 수 있어, 같은 쪽 번호가 같은 내용을 뜻하지는 않습니다.
> 화면에도 이 주의 문구가 표시됩니다.

### 오른쪽 위 — 수정본 비교

```
비교 기준: 최초 제출 (검토 완료된 마지막 버전) → 수정 1차

  의료비 합계   [값 변경]   5p 보기
  1,240,000  →  1,580,000

  의료비 10월   [신규 항목]   3p 보기
  (이전 없음)  →  340,000
```

**비교 기준은 '직전 제출본'이 아니라 '가장 최근 검토 완료 버전'입니다.**

```
V1 검토완료 → V2 미검토 → V3 제출
   ↑ 여기가 기준 (V2를 아무도 안 봤으므로)
```

검토 완료된 버전이 없으면 직전 제출본과 비교하되 **'최초 검토 미완료'** 를 표시합니다.

### 변경 종류 5가지

| | 뜻 |
|---|---|
| 신규 항목 | 이번에 새로 나타남 |
| 값 변경 | 금액·날짜 등이 달라짐 |
| **기존 항목 미발견** | 이번에 못 찾음 — **삭제로 확정하지 않습니다** |
| 비교값 동일 | 같음 (접어서 표시) |
| 추출·대응 확인 필요 | 연결이 불확실함 |

### 경고 표시

읽기가 불완전하거나 판단이 위험하면 **먼저 빨간 상자로 알립니다.**

- "읽지 못한 페이지가 있습니다. 이 결과만으로 변경 없음을 판단하지 마세요."
- **"합계 금액은 같지만 세부내역이 달라졌습니다."**
- "자동 추출을 지원하지 않는 서식입니다."

### 오른쪽 아래 — 추출 결과

항목별로 값·근거 페이지·추출 방식(텍스트/OCR)이 나옵니다.

**값을 고칠 수 있습니다.** 고쳐도 원래 읽은 원문은 그대로 남고,
누가 언제 고쳤는지가 기록됩니다.

```
기부금액   [150000        ] [저장]
           원문: 150,000
           ↳ 15001 → 150000 · 임종욱 · 01/12 09:20
```

### 검토 완료

- 현재 버전이 아니면 완료 버튼이 동작하지 않습니다
- **원본을 한 장도 띄울 수 없는 파일은 앱에서 완료할 수 없습니다**
- 읽지 못한 페이지가 있으면 **원본을 직접 확인했다는 사유**를 적어야 완료됩니다

## 지원 서식

| 서류 | 근거 서식 | 자동 추출 항목 |
|---|---|---|
| **기부금영수증** | 소득세법 시행규칙 [별지 제45호의2서식] (2022.3.18. 개정) | 일련번호, 기부자 성명·주소, 단체명·사업자등록번호, 근거법령, 기부내역(코드·연월일·품명·금액), 합계 |
| **간소화자료** | 「OOOO년 귀속 소득ㆍ세액공제증명서류 : 기본내역 [항목]」 | 귀속연도, 항목, 가입자 성명·주민등록번호, 월별 금액, 합계 |
| **기타** | — | 자동 추출 없음. 원본 조회 + 수동 검토 기록 |

> **가상 서식으로만 검증했습니다.** 홈택스 원본 전체 지원을 주장하지 않으며,
> 임의 기관의 모든 영수증 양식을 자동 처리하지 않습니다.

### 합계는 내역에서 계산합니다

기부금영수증 서식에는 합계란이 없습니다. 내역을 더해서 만듭니다.
그래서 **총액이 같아도 내역이 바뀌면 잡아냅니다.**

```
최초본:  정기 200,000 + 일시 100,000 = 300,000
수정본:  정기 150,000 + 일시 150,000 = 300,000   ← 합계 동일, 내역 변경 → 경고
```

## OCR

스캔된 PDF(글자가 없는 이미지 PDF)는 OCR로 읽습니다.

| 환경 | OCR |
|---|---|
| 로컬 실행 | **동작** (Tesseract 한국어) |
| Vercel 배포본 | **동작 안 함** — 서버리스에 시스템 바이너리 설치 불가 |

**OCR이 없어도 앱은 정상 동작합니다.** 다만 스캔 PDF는 값을 추측하지 않고
`추출 확인 필요`로 남깁니다. 화면 상단에 OCR 사용 불가 상태가 표시됩니다.

> ONNX 기반 대안을 실제로 검증했으나 채택하지 않았습니다.
> 한국어 모델이 **150,000을 15001로 오독**해 금액 검증의 신뢰성을 해칩니다.
> 부정확한 OCR보다 "못 읽었습니다"가 낫다고 판단했습니다.

## 보안 · 개인정보

- 원본 PDF는 **비공개 저장소**에만 두고, 권한 확인 후 앱이 직접 내보냅니다
- `static` 폴더에 두지 않습니다. 링크를 알아도 접근할 수 없습니다
- 저장 파일명은 서버가 생성합니다. 업로드 파일명을 경로로 쓰지 않습니다
- 배정되지 않은 직원의 자료는 목록·원본·CSV 어디에도 나오지 않습니다
- 비밀번호·PDF 본문·주민등록번호는 로그에 남기지 않습니다
- **외부 OCR·AI API를 호출하지 않습니다**
- 로그인은 세션 기반, 비밀번호는 해시 저장, 폼은 CSRF 보호

> 원본에 포함된 개인정보가 자동으로 익명화되지는 **않습니다.**

## 검증

```bash
python verify.py
```

체크리스트 **16항목 자동 검증**. 통과/실패를 그대로 출력합니다. 전항목 통과 상태입니다.

주요 항목:
- 담당자 A가 담당자 B의 자료에 접근 불가
- 새 서류 추가 시 기존 완료 서류는 그대로
- 동일 파일 재제출이 새 버전·분모를 만들지 않음
- 100,000 → 150,000 변경이 근거 페이지와 함께 표시
- **합계가 같아도 세부내역 변경을 잡아냄**
- **읽기 실패가 '변경 없음'이나 0으로 처리되지 않음**
- V1완료 → V2미검토 → V3제출 시 기준이 V1
- 값을 고쳐도 원문·수정자·시각 보존
- 암호화·손상 PDF가 앱을 멈추지 않음

## 시연 순서 (3분)

1. **로그인** → 검토 현황. "6건 중 5건이 다시 봐야 할 상태입니다"
2. **행복나눔재단 기부금영수증** → 100,000 → 150,000 변경 감지, 근거 페이지 클릭
3. **나란히 보기** → 기준본과 수정본 원본을 좌우로 대조
4. **연화사 영수증** → 합계 300,000 그대로인데 내역만 바뀐 것을 잡아내는 경고
5. **판독 불가 스캔** → 값을 지어내지 않고 '추출 확인 필요'로 남는 것

4번이 가장 설득력 있습니다. 합계만 보면 놓치는 것을 잡아내는 장면입니다.
