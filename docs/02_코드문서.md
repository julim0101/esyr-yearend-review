## 2. 데이터 모델 — 개념 4개 분리가 전부다

`models.py`

| 모델 | 뜻 |
|---|---|
| **DocumentGroup** | 하나의 논리적 서류. "A기관 기부금영수증" |
| **DocumentVersion** | 그 서류의 제출본. 최초본 / 수정1차 / 수정2차 |
| **ExtractionRun** | 한 버전을 *읽은* 결과 판본. 재추출하면 `revision_no` 증가 |
| **Review** | 특정 버전 + 특정 판본에 대한 담당자 확인 기록 |

**문서 버전과 추출 판본을 절대 혼동하지 않는다.**
같은 원본을 OCR로 다시 읽었다고 제출 버전이 늘어나면 안 된다.
재추출은 새 판본으로 저장하고, 이미 완료된 검토가 참조한 판본은 그대로 둔다.

### 상태를 두 축으로 분리

```python
class RunStatus:    # 기계가 정한다
    PENDING / RUNNING / SUCCESS / PARTIAL / FAILED

class ReviewState:  # 사람이 정한다
    NEW / RECHECK / EXTRACT_CHECK / DONE
```

읽기가 실패하면 검토 상태는 `EXTRACT_CHECK`.
사람이 원본으로 직접 확인하면 **추출 실패 기록은 그대로 두고** 검토 상태만 `DONE`으로 바꾼다.

### 핵심 컬럼

- `DocumentGroup.last_reviewed_version_id` — 비교 기준을 고르는 근거
- `DocumentVersion.render_ok` — 원본을 한 장도 못 띄우면 완료 불가로 막는다
- `Comparison.base_is_reviewed` — False면 화면에 '최초 검토 미완료' 표시
- `Review.manual_reason` — 추출 실패분을 사람이 직접 봤을 때의 사유

## 3. PDF 읽기 — `extract.py`

### 페이지별 판정

```python
TEXT_MIN_CHARS = 40   # 미만이면 "텍스트 레이어 없음" → OCR 대상

text = page.get_text("text")
if len(text.strip()) >= TEXT_MIN_CHARS:
    method = "text"
elif ocr_available:
    method = "ocr"    # 해상도 3배로 올려야 한글이 읽힌다
else:
    method = None     # 못 읽었다고 기록. 추측하지 않는다
```

> 글자가 몇 개 나온다고 페이지 전체를 정상 추출했다고 판단하지 않는다.

### 값 정규화 — 표현 차이만 제거한다

```python
norm_amount("150,000원")  → "150000"
norm_amount("읽을수없음")  → None       # ← 0으로 바꾸지 않는다
norm_date("2025.03.14")   → "2025-03-14"
```

**읽지 못한 값을 0이나 빈 문자열로 바꾸면 '변경 없음'이 되어버린다.** 그래서 `None`을 유지한다.

### 서식별 파서

실제 서식 구조를 조사해서 그대로 맞췄다.

**기부금영수증** — 소득세법 시행규칙 [별지 제45호의2서식] (2022.3.18. 개정)
```
일련번호
① 기부자      : 성명(법인명) | 주민등록번호 / 주소(소재지)
② 기부금 단체  : 단체명 | 사업자등록번호 / 소재지 / 근거법령
③ 기부금 모집처(언론기관 등)
④ 기부내용     : 코드 | 구분 | 연월일 | 품명 | 수량 | 단가 | 금액
```

**간소화자료** — 「OOOO년 귀속 소득ㆍ세액공제증명서류 : 기본내역 [항목]」
```
제목 · 조회기간
가입자 인적사항 : 성명 | 주민등록번호
월별 내역표     : 월별 | 지출금액 | 공제대상금액 ... 합계
```

인식 실패는 정직하게 반환한다.

```python
if "기부금" not in full:
    return [], False      # recognized=False. 억지로 뽑지 않는다
```

미지원 서식은 원본 조회 + 수동 검토 경로를 제공하고 화면에 명시한다.

### 항목 연결 키

금액으로 연결하면 안 된다. **식별정보를 키에 넣는다.**

```
간소화자료  : "의료비::김하늘::10월"
기부금영수증 : "detail::2025-05-10::정기법보시"
합계        : "amount"
```

대상자를 구분할 수 없으면 `unknown`을 넣고 수동 확인 대상으로 남긴다.
업로드한 직원 본인의 지출로 단정하지 않는다.

### 합계는 내역에서 계산한다

기부금영수증 서식에는 합계란이 없다. 내역을 더해서 만든다.
그래서 **합계가 같아도 내역이 바뀌면 잡힌다.**

## 4. 비교 엔진 — `compare.py`

### 비교 기준은 "가장 최근 검토 완료 버전"

```
V1 검토완료 → V2 미검토 → V3 제출
   ↑ 기준        ↑ 여기가 기준이 되면 V1→V2 변경분이 영원히 묻힌다
```

```python
reviewed = [v for v in candidates if v.is_reviewed]
if reviewed:
    return max(reviewed, key=lambda v: v.seq), True
return max(candidates, key=lambda v: v.seq), False   # 직전본 + '미완료' 표시
```

### 변경 종류 5가지

| | 뜻 |
|---|---|
| `added` | 신규 항목 |
| `changed` | 값 변경 |
| `missing` | 기존 항목 미발견 — **삭제로 확정하지 않는다** |
| `same` | 비교값 동일 |
| `uncertain` | 추출·대응 확인 필요 |

### 신뢰할 수 없으면 먼저 경고한다

```python
if new_run.status == PARTIAL:
    warnings.append("읽지 못한 페이지가 있습니다. 변경 없음을 판단하지 마세요.")
if detail_changed and total_same:
    warnings.append("합계 금액은 같지만 세부내역이 달라졌습니다.")
```

## 5. 저장소 추상화 — `storage.py`

로컬과 서버리스를 같은 코드로 쓰기 위해 분리했다.

```python
save_bytes(name, data)   # 로컬 파일 또는 Supabase Storage
read_bytes(name)
local_path(name)         # PyMuPDF가 읽을 실제 경로. 원격이면 임시 파일로 내려받음
```

환경변수 `SUPABASE_URL` / `SUPABASE_SERVICE_KEY` / `SUPABASE_BUCKET`이 셋 다 있으면
Supabase Storage, 없으면 로컬 파일.

> 서버리스는 파일시스템이 **읽기 전용**이다. `os.makedirs`가 앱을 죽인다.
> 예외 처리해서 "이 환경에서는 로컬 저장을 쓸 수 없습니다"로 안내한다.

## 6. 권한 — `routes.py`

```python
def require_employee(emp_id):
    emp = db.session.get(Employee, emp_id)
    if not g.user.is_admin and emp.manager_id != g.user.id:
        abort(403, "배정되지 않은 직원의 자료입니다.")
```

원본 PDF·페이지 이미지·CSV **전부** 이 검사를 통과해야 나간다.
`static` 폴더에 두지 않고 인증된 경로로만 내보낸다.
저장 이름은 서버가 생성하고, 업로드 파일명을 경로로 쓰지 않는다.

### 중복 판정 — 파일명이 아니라 해시

```
현재 버전과 바이트 동일  → 중복 접수. 새 버전 없음. 상태 유지
과거 버전과만 동일       → "과거 제출본 재등록". 현재 상태를 되돌리지 않음
파일명만 같고 내용 다름  → 정상적인 수정 후보
```

중복 확인 범위를 해당 묶음 안으로 제한한다.
다른 직원 자료의 존재가 메시지로 새어나가면 안 된다.

### 완료 처리 조건

```python
if grp.current_version_id != ver.id:
    → "이 버전은 더 이상 현재 버전이 아닙니다"
if not ver.render_ok:
    → "원본을 표시할 수 없어 앱에서 완료할 수 없습니다"
if run.has_unread and not manual_reason:
    → "원본을 직접 확인한 사유를 남겨야 완료할 수 있습니다"
```

## 7. 실제로 밟은 함정

### 7-1. SQLAlchemy 관계 캐시

같은 세션에서 `run_extraction()` 직후 `version.runs`를 읽으면 **갱신 전 빈 목록**이 나온다.
비교가 "새 버전의 추출 결과가 없습니다"로 실패했다.

→ 관계 대신 직접 조회로 바꿨다.

```python
@property
def latest_run(self):
    return ExtractionRun.query.filter_by(version_id=self.id) \
        .order_by(ExtractionRun.revision_no.desc()).first()
```

### 7-2. 그런데 그게 목록 화면을 27초로 만들었다

프로퍼티가 매번 DB를 조회하는데, 대시보드가 묶음마다 3번씩 호출했다. 왕복 50회 이상.

→ 목록에서는 **통째로 가져와 파이썬에서 조립**한다. (`build_group_states`)

```python
versions = DocumentVersion.query.filter(...).all()   # 1회
runs     = ExtractionRun.query.filter(...).all()     # 1회
reviews  = Review.query.filter(...).all()            # 1회
cmps     = Comparison.query.filter(...).all()        # 1회
```

### 7-3. 함수 리전과 DB 리전이 달랐다

Vercel 기본 리전은 미국, Supabase는 서울. 왕복마다 수백 ms.

→ `vercel.json`에 `"regions": ["icn1"]`

**27.5초 → 0.23초** (약 90배)

### 7-4. 비밀번호 해시가 3초

Werkzeug 기본값 `scrypt`는 의도적으로 CPU를 많이 쓴다. 서버리스의 약한 CPU에서 느리다.

→ `pbkdf2:sha256:120000`으로 변경. **3.0초 → 0.55초**

### 7-5. Vercel 번들 용량 초과 (292MB > 225MB)

`psycopg[binary]`가 수십 MB.

→ **pg8000**(순수 파이썬 Postgres 드라이버)으로 교체 + `.vercelignore`로 샘플·모델 제외

### 7-6. PowerShell 파이프가 환경변수를 깨뜨린다

`$value | vercel env add KEY` 하면 BOM·개행이 섞여 들어가
`Could not parse SQLAlchemy URL` 에러가 났다.

→ bash `printf '%s'`로 등록. 앱에도 `lstrip("﻿")` 방어 추가.

### 7-7. OCR 관련

`references/ocr-setup.md`(스킬) 참조. 요약하면:
- pytesseract는 래퍼일 뿐, 엔진과 언어데이터는 별도 설치
- 언어데이터 경로에 한글·공백이 있으면 실패
- config 문자열에 따옴표를 붙이면 경로의 일부가 된다
- `get_languages()`는 한국어 Windows에서 인코딩 에러

## 8. 배포 구성

```
GitHub    julim0101/esyr-yearend-review
   ↓
Vercel    esyr-yearend-review.vercel.app   (리전 icn1)
   ↓
Supabase  Postgres (ap-northeast-2) + Storage 비공개 버킷 esyr-docs
```

| 환경변수 | 용도 |
|---|---|
| `DATABASE_URL` | Supabase Postgres (Transaction pooler, 6543) |
| `SUPABASE_URL` / `SUPABASE_SERVICE_KEY` / `SUPABASE_BUCKET` | 원본 PDF 보관 |
| `ESYR_SECRET_KEY` | 세션 서명 |

환경변수가 없으면 로컬(SQLite + 파일)로 동작한다. 같은 코드다.

### 배포본의 제약

**OCR이 동작하지 않는다.** 서버리스에 Tesseract 바이너리를 설치할 수 없다.
스캔 PDF는 값을 추측하지 않고 `추출 확인 필요`로 남는다.

ONNX 기반 대안(`rapidocr-onnxruntime`)을 실측했으나 **한국어 모델이 금액을 오독**해
(150,000 → 15001) 채택하지 않았다.

> 부정확한 OCR을 넣느니 "못 읽었습니다"라고 말하는 게 낫다.

## 10. 이 도구가 하지 않는 것

- 공제 적격 여부 판정
- 세액 계산
- 위변조 판정
- 원천 인사자료와의 일치 확인
- 외부 OCR·AI API 호출

'검토 완료'는 **담당자가 해당 자료 버전을 확인했다는 뜻**이다.
세법상 판정이나 신고 완료가 아니다. 화면과 CSV에도 그렇게 표시한다.
